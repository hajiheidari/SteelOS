مؤسس در2026-10-27 این چهار نقش را قبل از حسابداری اولویت داد. حسابداری/فرآیند مرجع
پیش‌نیاز آنها نیست. این بسته یک فضای کاری داخلیِ تولید، ثبت شواهد و بازبینی است؛
تحقیق خودمختار وب، انتشار، پیام‌رسانی مشتری و تصمیم مالی را پیاده‌شده معرفی نمی‌کند.

قیمت واقعی همچنان از دستیار فروش فقط‌خواندنی و API قیمت تأییدشده می‌آید، و سند داخلی
از workflow انسانی SALES_DRAFTS.md؛ این تولیدکنندهٔ متن حق اعلام قیمت/موجودی یا صدور ندارد.

## جریان کار و مرز دانش

مدیر متن مجاز1500نویسه‌ای را با نام/انتساب و تأیید صریح اجازهٔ استفاده ثبت می‌کند.
نوع public_excerpt نشانی HTTPS بدون credential می‌خواهد؛ نشانی صرفاً metadata است و
هیچ HTTP retrieval یا scraping انجام نمی‌شود. تأیید مدیر، بررسی خودکار مجوز/درستی منبع نیست.
منبع و محتوایش بازنویسی/حذف نمی‌شوند؛ اصلاح با ثبت منبع تازه و لغو اعتبار قبلی است.

کارشناس/مدیر نقش، brief تا1000نویسه و حداکثر۳ منبع را انتخاب می‌کند. بدون منبع فقط
طرح/نمونهٔ اولیه با grounding=no_sources_plan_only تولید می‌شود، نه یافتهٔ تحقیق.
با منبع، مدل حداقل یک نقل‌قول دقیق از متن ورودی می‌دهد؛ استنادهای هر بخش اختیاری‌اند
ولی باید زیرمجموعهٔ نقل‌قول‌های معتبر باشند. نقل‌قول پایانی سند هم معتبر است؛ هیچ‌کدام
به معنی پشتیبانی معناییِ همهٔ جمله‌ها نیست. صحت ادعاها همواره human_required است.

سه بخشِ ثابتِ هر نقش، متن فارسی، نبود تکرار دقیق بین بخش‌ها، source alias شناخته‌شده
و نقل‌قول پیوستهٔ عین متن بررسی می‌شوند. خروجی نامعتبر ذخیره نمی‌شود. این بررسی ساختاری/
واژگانی جای ارزیابی زبانی، آموزشی یا صحت علمی/بازاری را نمی‌گیرد. مدل محلی کوچک ممکن
است متن نامفهوم/تکراری/ناقص بسازد؛ شواهد ناکافی مدل1.7B در evidence/INTERNAL_AGENTS_MODEL_OBSERVATIONS.md ثبت‌اند.

فقط مدیر یک بار برای همان run پذیرش داخلی یا رد با یادداشت ثبت می‌کند. تغییر نیاز به
run تازه دارد. پذیرش داخلی مجوز انتشار/ارسال یا financial approval نیست. لغو هر منبع
ورودی، evidence_current را در سوابق وابسته false می‌کند؛ متن/تصمیم تاریخی پاک نمی‌شود.

## API و مجوز

همهٔ مسیرها زیر /api/v1/agent-workbench و نیازمند نشست/عضویت جاری‌اند:

- GET /status: وضعیت پیکربندی، نه اثبات حاضر بودن مدل.
- GET /sources: q/active و pagination25/default,100/max؛ همهٔ اعضای همان سازمان می‌خوانند.
- POST /sources: فقط مدیر، rights_confirmed=true به‌صورت bool صریح؛ Idempotency-Key لازم.
- POST /sources/{id}/revoke: فقط مدیر، idempotent، برگشت‌ناپذیر در API.
- POST /runs: مدیر/کارشناس، Idempotency-Key، kind و brief/source_ids؛ viewer403.
- GET /runs و /runs/{id}: همان سازمان؛ فیلتر kind و pagination روی فهرست.
- POST /runs/{id}/review: فقط مدیر، decision=accepted|rejected و یادداشت؛ یک تصمیم برای هر run.

منابع، run، evidence و review UUID و tenant scope دارند؛ FKهای مرکب از اتصال بین سازمان‌ها
جلوگیری می‌کنند. triggerهای PostgreSQL تغییر/حذف تاریخچه و بازنویسی/فعال‌سازی مجدد منبع
لغوشده را رد می‌کنند. اینها در برابر UPDATE/DELETE هستند؛ DB operator همچنان privileged است.
هیچ endpoint نوشتن مالی، موجودی، قیمت تأییدشده یا ارسال بیرونی به مدل داده نمی‌شود.

## استنتاج محدود و بازاعتبارسنجی

provider مستقل به‌صورت پیش‌فرض disabled است. فقط Ollama محلی با URL allowlist موجود
و model tagهای صریح مجاز است؛ فروش قبلی همچنان مدل مستقل qwen3:1.7b خود را حفظ می‌کند.
مدل مرکز ایجنت‌ها qwen3:4b-instruct-2507-q4_K_M است؛ license layer رسمی Apache2 مشاهده شد،
اما آزمون کیفیت این مدل هنگام ثبت اولیهٔ بسته هنوز تکمیل نشده و آمادگی آن ادعا نمی‌شود.

مدل فقط brief و alias/content منابع را می‌گیرد؛ org/source IDs، توکن، URL، نتایج DB یا
ابزار دریافت نمی‌کند. متنِ مجازِ مدیر می‌تواند خصوصی باشد و عمداً برای استنتاج محلی
فرستاده می‌شود؛ از منابع حاوی اطلاعات غیرمجاز استفاده نکنید. proxy خارجی، redirect و
cloud مدل فعال نیستند. یک استنتاج در هر worker، context8192، سقف1280 توکن خروجی، پاسخ96KiB
و deadline120ثانیه داریم؛ proxy فقط همین POST را تا135ثانیه انتظار می‌کشد. صف/Redis/worker تازه نداریم.

قفل/connection DB در زمان inference آزاد می‌شود. پس از آن نشست، عضویت/role، replay و اعتبار
منابع دوباره بررسی و قفل می‌شوند؛ سپس run/evidence/audit/key در یک تراکنش ثبت می‌شوند.
خطا/لغو دسترسی/منبع لغوشده، run یا کلید مصرف‌شده باقی نمی‌گذارد. UI کلید retry همان
درخواست را تا موفقیت حفظ می‌کند. از policy_version=internal-agents-v2، هر بخش مدل حداکثر۱۸۰ نویسه، عنوان۱۰۰ نویسه
و یک پرسش حداکثر۱۰۰ نویسه است؛ مهلت/استناد/مجوزها افزایش یا تضعیف نشده‌اند. قرارداد
نمایش تاریخچه همچنان خروجی نسخهٔ اول را می‌خواند و سوابق قبلی بازنویسی نمی‌شوند.
در v3 جمله‌های بدون پایانِ نقطه/علامت پرسش/تعجب/سه‌نقطه رد می‌شوند؛ پایان نقل‌قول
یا پرانتز پس از این نشانه مجاز است. این یک guard واژگانی برای قطع آشکار جمله است، نه
اثبات دستور زبان یا صحت مفهوم. متن ناقص بی‌صدا بریده یا تکمیل نمی‌شود. دستور داخلی
کوتاه‌تر و روشن‌تر است؛ زبان خروجی همچنان فارسی است و بازبینی انسانی ضروری می‌ماند.
policy_version و model_name همراه خروجی ذخیره می‌شوند؛
اینها به‌تنهایی تضمین تکرارپذیری bit-for-bit مدل نیستند.

## راه‌اندازی اختیاری محلی

برنامه/CI بدون مدل و بدون دانلود وزن کار می‌کنند؛ هیچ دانلود خودکار در API وجود ندارد.
برای تست محلی و فقط اگر RAM/disk کافی دارید، از همان runtime اختیاری موجود استفاده کنید:

```sh
OLLAMA_MEMORY_LIMIT=6g docker compose --profile assistant-local up -d ollama
# فقط انتخاب اختیاری اپراتور؛ مدل رایگان با license رسمی، نه گام اجباری setup/CI:
docker compose --profile assistant-local exec ollama ollama pull qwen3:4b-instruct-2507-q4_K_M
AGENT_WORKBENCH_PROVIDER=ollama OLLAMA_MEMORY_LIMIT=6g docker compose --profile assistant-local up -d api ollama
```

در اجرای مستقیم API، AGENT_WORKBENCH_PROVIDER=ollama و ASSISTANT_OLLAMA_URL آدرس محلی
Ollama هستند؛ AGENT_WORKBENCH_MODEL مدل مستقل مرکز است. برای4B context بزرگ، حدود۶GiB
بودجهٔ runtime و فضای کافی وزن/تصویر لازم است؛ هیچ RAM/storage یا سرویس پولی provision نشده.
وزن‌ها در CI دانلود نمی‌شوند. ارزیابی واقعیِ اختیاری با ورودی ثابت و مصنوعی، بدون DB:

```sh
PYTHONPATH=apps/api .venv/bin/python apps/api/tests/evaluate_agent_workbench.py --run-local-model --output /tmp/internal-agents-evaluation.json
```

این script دانلود نمی‌کند؛ تنها مدل از قبل موجود را فراخوانی و نتیجه/شکست مصنوعی را ثبت می‌کند.
فایل نتیجه در شروع با started_at و completed=false جایگزین می‌شود؛ پس از هر نقش به‌صورت
اتمیک ذخیره و فقط پس از پایان هر چهار مورد completed=true می‌شود. passed صرفاً عبور
از قرارداد ساختاری/نقل‌قول است؛ quality_acceptance=not_assessed_by_script به معنی نیاز
به بازبینی مستقل کیفیت است. قطع اجرا، موفقیت قدیمی را به اجرای تازه نسبت نمی‌دهد.
خواندن دانش/تاریخچه با provider disabled ممکن است. حسابداری، منابع خارجیِ خودکار، آموزش
تعاملی/ارزیابی پیشرفت، کمپین و کانال‌های واقعی یا agent مستقلِ بدون انسان از این بسته نتیجه نمی‌شوند.
