# دامنهٔ batch بعد: پیش‌نویس داخلی پیش‌فاکتور فروش

در ادامهٔ درخواست founder برای پیشبرد کل پروژه، پس از foundation و انبار، یک سند
داخلی قابل بازبینی برای فروش ایجاد می‌شود. این مرحله پیش‌فاکتور مالی نهایی یا تعهد ارسال‌شده
به مشتری نیست و هیچ پیام خارجی، رزرو خودکار، تغییر مالکیت، دریافت وجه، journal یا tax filing ندارد.

## قرارداد پیشنهادی پیاده‌سازی

- سازمان و اختیار از session/membership؛ viewer خواندن، editor/admin ایجاد و ویرایش draft.
- مشتری باید party فعال با نقش customer همان سازمان باشد. نقش supplier هم‌زمان مجاز است.
- کد یکتا در سازمان، ارز صریح، یادداشت، ردیف‌ها و نسخهٔ optimistic concurrency.
- ردیف به price observation تأییدشده و معتبر همان سازمان متصل است؛ محصول، واحد، قیمت،
  ارز، زمان، provenance، delivery و tax_included از منبع API snapshot می‌شوند، نه مبلغ دلخواه کلاینت.
- quantity رشتهٔ Decimal مثبت با حداکثر سه اعشار؛ قطعه عدد صحیح. تبدیل واحد/ارز ضمنی وجود ندارد.
- برآورد خام quantity × unit_price با محاسبهٔ دقیق Decimal و نمایش صریحِ گردنشده؛ مالیات
  جدید، تخفیف، حمل و مبلغ قانونیِ نهایی محاسبه نمی‌شود. قواعد گردکردن/مالیات باید از founder برسد.
- انقضای بعدی یا لغو منبع در خواندن سند نشان داده می‌شود؛ snapshot تاریخچه را تغییر نمی‌دهد.
- ویرایش سند با نسخهٔ موردانتظار و idempotency؛ revisionهای قبلی باقی می‌مانند.
- لغو draft به‌جای حذف تاریخچه. مسیر approved/customer-export در این batch وجود ندارد.
- API /api/v1، migration، UI فارسی، audit و تست tenant/precision/expiry/concurrency.

## تصمیم کسب‌وکار لازم برای مرحلهٔ مالی بعد

روش واقعی گردکردن مبلغ هر ردیف/جمع و نحوهٔ درج یا تفکیک مالیات در پیش‌فاکتورهای فعلی.
از هیچ نرخ مالیاتی فرضی یا ضابطهٔ قانونی اختراعی استفاده نمی‌شود. دریافت این پاسخ شرط
توسعهٔ تأیید مالی و خروجی مشتری است، نه مانع پیاده‌سازی draft داخلی بالا.
